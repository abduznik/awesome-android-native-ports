# Contribution Guidelines

Please ensure your pull request adheres to the following guidelines:

- Search previous suggestions before making a new one, as yours may be a duplicate.
- Make sure the project is public and has a working Android build: an APK in the releases, a CI artifact, or a documented way to build one. Ports that only plan Android support do not belong here.
- The port must run natively. Emulators, Wine, Box64 or Winlator wrappers and streaming clients are out of scope.
- The project must not distribute copyrighted game data. Players supply their own game files, disc images or ROMs.
- Make sure the project is actively maintained (a commit or release in the last 12 months). Older but still working ports go in the Classic Ports section.
- Projects should have at least 8 stars or a clear reason to be listed, such as being the first Android port of a game. Very new projects are welcome once they have a usable release.
- Make an individual pull request for each suggestion.
- Use the format: `| [Game Name](repo-url) | Short description of what it is and which Android builds it offers. | [Author](author-url) |`
- Descriptions should be concise (one sentence), start with a capital letter, and end with a period.
- Keep each section in alphabetical order by game name.
- Place the entry under the correct section. If the technique or toolchain does not exist yet, add a new section with a link to its repository.
- If a game has several Android ports, list each one and say how it differs.
- New categories or improvements to the existing categorization are welcome.
- Check your spelling and grammar.
- The pull request and commit should have a useful title, e.g. `Add [Game Name]`.

Thank you for your suggestions!
